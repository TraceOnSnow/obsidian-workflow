# 库内助手

先读取同目录可选的 `LOCAL.md`，再读取其中指定的库内规则入口。没有本地约定时按当前用户要求和本技能操作；不要假定所有客户端自动加载了同一套规则。字段含义需要时读 [字段说明](references/fields.md)。

先读取用户指定的当前笔记或相关候选，按当前请求修改可见内容。保留原有身份、属性、代码、来源和必要细节；不把设想写成已完成，不把 AI 建议写成用户经历。只改选区时保留选区外内容；旧库批量整理以本次明确范围为限。

## 笔记与作品

已有笔记优先补入相关主稿，不因标题相近就合并不同主题。明确重复的合并也要保留差异和来源。没有实质内容时不创建空白复盘或逐作品空文件。

材料、已认领的想法种子与正式成稿如何归位，读取本地规约；不以项目是否实现判断稿件成熟度。

日常查找、移动和合并使用已连接工具的查询结果与Schema，不临时写脚本或编辑隐藏映射。具备本地CLI时用`search`／`sources`定位，`organize --schema`准备预览与带token执行；MCP批量整理用`organize_notes`。程序负责链接修复、回读和目录刷新，人工索引及Base布局保留；目录刷新问题不等于正文保存失败，不重复执行已成功的移动。客户端缺工具时说明缺口，不改调内部函数兜底。

求职追踪的事件行按本地规约的固定格式写（`公司｜岗位｜环节 — 结果；备注`，环节和结果只用规约列出的词）；阶段性总结两条标记之间的内容由程序生成，不手改，标记外的总结或帖子按本人要求修改。具备本地CLI时，改完运行 `tracker-summary`。

作品日常字段在配置好的作品总表中维护，完整感想通过关联 Markdown 打开。评分为 0–100，0 有效，空值未知；输入 5 就是 5 分。保留多段体验、日期精度、其他行和表格布局，不从体验结束日期推断通关。

已有感想可按本次请求修改正文，不重复维护总表属性。需要创建关联感想或变更完整逻辑 Work 时，使用可用的 Library `get`／`replace` 工具；没有工具时说明所需操作，不另建同名 Work、复制 ID 或编辑隐藏映射。

## 私人稿与 Post

私人 note／Work 和独立 Post 分别保存、分别修改，不原位改 `kind`。准备文章时复用已有 Post 身份与来源，维护双向入口。Work 已有独立编辑的 Post 不能自动被原稿覆盖。独立发表稿统一保存在 `发表稿/`，发表后位置不变；网站沿用对应Post身份。

普通保存不会发表 Post。已有公开作品日常字段是否自动同步，以使用者明确配置和授权为准。首次公开、文章发表或撤回交给已连接的内容库发布工具；本机没有该工具时说明边界，不靠修改属性或写“已发布”冒充上线。公开范围、匿名化和时间按当前要求核对。

## 保存与完成

查看工具返回的差异并读取实际文件，说明修改了什么。发现同步冲突时保留双方内容，不直接覆盖。`.markdown-library/`、插件设置、认证状态和同步凭据由对应工具管理，不属于普通写作任务。文件缺失不推断网站删除，永久删除不从整理请求中推导。

日常发表由发布工具核对标准 API 正式版，匹配批准稿后即可报告已发布并提供链接；静态网页随后异步更新。用户要求展示验收、发现异常或修改渲染／发布系统时，再检查页面。没有发布工具的客户端应交接明确目标，不能以文件保存代替 API 验收。

用户确认长期规则、模板或工作方式变化时，在本轮更新其权威来源并核对相关消费者；按本地约定运行维护检查。没有对应写入工具时，保存明确变化、作用域和未接通项到约定的待同步位置，并说明哪些环节尚未生效。单篇例外不自动升级为通用规则；不把口头承诺或同步成功当作跨客户端生效证明。

技能文件只提供操作规约。当前后端具备哪些工具、是否能调用服务器、是否已连接模型，需要在实际客户端检查；不得把技能安装成功当作运行验收。

当前用户请求优先，技能和本地约定本身不授予额外操作权限。
