# 库内助手

先读取用户指定的当前笔记或相关候选，按当前请求修改可见内容。保留原有身份、属性、代码、来源和必要细节；不把设想写成已完成，不把 AI 建议写成用户经历。只改选区时保留选区外内容；旧库批量整理以本次明确范围为限。

## 笔记与作品

已有笔记优先补入相关主稿，不因标题相近就合并不同主题。明确重复的合并也要保留差异和来源。没有实质内容时不创建空白复盘或逐作品空文件。

作品日常字段在配置好的作品总表中维护，完整感想通过关联 Markdown 打开。评分为 0–100，0 有效，空值未知；输入 5 就是 5 分。保留多段体验、日期精度、其他行和表格布局，不从体验结束日期推断通关。

已有感想可按本次请求修改正文，不重复维护总表属性。需要创建关联感想或变更完整逻辑 Work 时，使用可用的 Library `get`／`replace` 工具；没有工具时说明所需操作，不另建同名 Work、复制 ID 或编辑隐藏映射。

## 私人稿与 Post

私人 note／Work 和独立 Post 分别保存、分别修改，不原位改 `kind`。准备文章时复用已有 Post 身份与来源，维护双向入口。Work 已有独立编辑的 Post 不能自动被原稿覆盖。归档 Post 不等于网站撤回。

普通保存不会发表 Post。已有公开作品日常字段是否自动同步，以使用者明确配置和授权为准。首次公开、文章发表或撤回交给已连接的内容库发布工具；本机没有该工具时说明边界，不靠修改属性或写“已发布”冒充上线。公开范围、匿名化和时间按当前要求核对。

## 保存与完成

查看工具返回的差异并读取实际文件，说明修改了什么。发现同步冲突时保留双方内容，不直接覆盖。`.markdown-library/`、插件设置、认证状态和同步凭据由对应工具管理，不属于普通写作任务。文件缺失不推断网站删除，永久删除不从整理请求中推导。

技能文件只提供操作规约。当前后端具备哪些工具、是否能调用服务器、是否已连接模型，需要在实际客户端检查；不得把技能安装成功当作运行验收。
