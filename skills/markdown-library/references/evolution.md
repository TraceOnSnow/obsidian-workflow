# 对话驱动的演进

目标：后续会话能读取并执行已经确认的新工作方式，维护技能本身也可被用户纠正。文件存在、同步成功和模型口头承诺都不能单独证明行为已经更新。

## 触发与记忆取舍

- 用户明确说“以后”“统一”“更新规约／模板”，或确认一种可复用的新处理方式，直接在本次授权范围内更新，不再索取同一确认。反复纠正行为是检查旧规则和调用入口的信号。
- 单次修稿、临时取舍和尚在讨论的建议保持原作用域；拿不准是否长期适用时先完成当前任务，只问影响未来行为的那个歧义，不把模型推测写成用户偏好。
- 用户后续改变想法时，读取当前有效规则及必要的旧决策理由，直接修订被替代条款。历史解释保留在原有交接／版本记录，不在每篇正文追加补丁，不无限追加互相冲突的禁令。
- 记忆保留简短规则、适用范围、必要理由和材料定位。运行状态必须按需观察；旧数量、旧失败状态和某次发布授权不成为持久操作指令。

## 一次更新如何完成

1. **读取**：从项目入口、当前技能及可选 LOCAL 找到对应现行规则和实际消费者。只读取这次相关材料，必要时定位原聊天，不重扫全部历史。
2. **定位权威来源**：在原有规则、模板或实现中修订，不为每次反馈另建记忆文件。规则留在规约，输出结构留在模板，确定性行为留在代码；维护方法的改变直接修改本技能或本参考。私人偏好与路径放本地文件，不带入公开共享技能。
3. **追踪影响**：查实际引用／调用，检查相关助手指令、模板源码与安装副本、指南、生成器及其输出。只更新受影响对象；避免把一条完整规则复制到所有层。能引用的使用引用，必须复制的内容核对差异并保留用户编辑。生成页同时维护生成源，不能只改会被覆盖的输出。
4. **落盘并验证**：沿用文件哈希、冲突守卫和原工具回读。规则文字改完不等于程序改完；需要代码、分发或客户端重载才能生效时，完成当前范围内的实现与相应核对。不得用重装覆盖已有本机改动，也不为学到一条规则重启现役服务。
5. **保留连续性**：在原有当前交接简记本次决定、原因／来源、涉及位置、已验证范围和未完成依赖。仅有真实未决项时记录待办。不要复制完整聊天或另造逐轮报告。下次相关任务先读取现行规则及未完成项，不依赖用户记得这次对话。
6. **报告**：简短说明更新到哪里、哪些环节已生效；分清规则已保存、实现已修改、客户端行为已验证。存在未更新的消费者时不能说“以后所有入口都已生效”。

## 对维护技能本身的反馈

若用户指出以上更新流程失效，定位失败发生在触发、检索、规则归属、分发还是验证；修改对应步骤，并用这次真实案例检查更新结果。不要仅新增“更认真遵守”的提醒，也不要把具体偏好塞进维护机制。发现重复副本冲突时修正实际读取的副本和其生成来源，维护路径改变时同步修改入口链接。

此流程在相关对话中执行，不是后台自动学习服务。它不新增公开、永久删除、付费调用或批量重写旧笔记的授权。若客户端没有加载入口或不具备写入工具，应明确未生效的边界并保留待接通项，不能声称获得跨客户端自动记忆。

## 可重复执行的维护检查

配置了维护清单的部署，在相关任务开始时先读取未处理的客户端反馈，结束前运行 `scripts/library-maintenance.py --vault VAULT --manifest MANIFEST`。清单指定规则来源、安装副本和需要人工核对的程序／模板依赖组；源码改变而说明仍相同时，依赖组也会要求审查。

预览是只读的，Agent根据实际差异修改相关来源或实现、运行相应检查，再以当前token执行apply。已有独立编辑必须先合并再显式接受已审定预览。执行后重新检查；仍有待同步反馈、差异或未审依赖时如实报告，不能以一次apply证明语义一致。首次接管旧副本要保存旧稿并审定差异；后续更新用共同维护基线保护用户编辑。

客户端没有服务器工具时，把用户明确确认的变化及适用范围保存到库内约定的待同步位置。后续具备工具的会话处理后，在原交接留下决定与生效范围，再移除已完成待办。Sync只传文件，不自动将待办当成已采纳规则。
